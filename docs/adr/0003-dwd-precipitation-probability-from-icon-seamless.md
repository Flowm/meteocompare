# DWD precipitation probability grafted from `icon_seamless` onto `icon_global`

open-meteo derives `precipitation_probability` only from ensemble members, so our three deterministic DWD ICON entries (`icon_global`, `icon_eu`, `icon_d2`) return null for it and DWD silently dropped out of the probability aggregate. We fetch the non-registered `icon_seamless` purely for `precipitation_probability` / `precipitation_probability_max` and read its series under `icon_global` (a _probability graft_ — see CONTEXT.md). DWD thus contributes exactly one probability vote; the deterministic entries keep their home-region weighting for every other variable, and `icon_seamless` never becomes a registry row, chip, or independent vote.

**Why `icon_global` and not a regional entry.** `icon_seamless` is itself seamless _along the lead axis_ — one series sourced from ICON-D2-EPS at short range, ICON-EU-EPS in the medium range, and ICON-EPS (global) for the long tail — so it returns ~171 non-null hours (~7 days) even at a point inside `icon_d2`'s home region. The graft target imposes that entry's `maxLeadHours` cutoff, after which the weight is zero. Routing onto `icon_d2` (48 h) or `icon_eu` (120 h) would truncate ~72 % / ~30 % of the series, deleting a legitimate DWD vote across the medium range. `icon_global` (180 h, global class, gentle long-range decay) is the only entry whose envelope contains the full series without truncation. The cost — DWD's probability forgoes a central-Europe home-region bonus on the high-resolution short-lead portion — is accepted as cheaper than losing coverage; recovering that bonus would require a probability-specific special case in the weighting recipe, which we judged not worth the complexity.

**Rejected alternatives.** (1) _Register `icon_seamless` as a Model_ — it returns every variable, so DWD would gain a fourth, near-duplicate ICON vote for temperature/precipitation/wind; a probability-only registry row would merely reinvent `icon_global`'s weight profile while adding a chip that is dead for six of seven variables. (2) _Compute probability ourselves from raw EPS members via the ensemble API_ — the ensemble API exposes members, not a derived probability, so this means a second API host, a member-aggregation step, and a precipitation threshold methodology; it also contradicts the deliberate "we don't use ensemble members" stance (CONTEXT.md → Aggregate), for marginal gain since `icon_seamless` already routes to the best-resolution regional EPS. (3) _Extend the graft to other providers_ — among the providers lacking native probability (Météo-France, UKMO, JMA, KMA, BOM), none expose any forecast-API ensemble, so there is no seamless source to graft from; DWD is the unique case where deterministic-only registry entries have an ensemble-backed seamless sibling.
